# Копирка для macOS

Десктопная упаковка «Копирки» на Tauri 2: окно с интерфейсом, иконка в строке меню,
глобальный хоткей на снимок области и локальный Node-сервер внутри бандла.

Ничего доустанавливать не нужно — Node, `sharp` и `better-sqlite3` лежат внутри `.app`.

## Что внутри

| Путь | Что это |
|---|---|
| `src-tauri/src/main.rs` | Запуск, меню, обработка выхода |
| `src-tauri/src/backend.rs` | Node-сервер как дочерний процесс: старт, health-check, гашение |
| `src-tauri/src/tray.rs` | Иконка строки меню и счётчик «Не разобрано» |
| `src-tauri/src/capture.rs` | ⌥⌘C: `screencapture -i` → `POST /api/import/capture` |
| `src-tauri/src/events.rs` | Уведомления обо всём, что прошло мимо окна, по `GET /api/events` |
| `src-tauri/src/notify.rs` | Показ баннеров через UNUserNotificationCenter |
| `src-tauri/src/windows.rs` | Главное и аварийное окна, полоса под светофор |
| `src-tauri/src/quickaction.rs` | Установка быстрой команды Finder «Добавить в Копирку» |
| `src-tauri/src/menu.rs` | Русское меню приложения; ⌘Q идёт через наш код |
| `src-tauri/src/http.rs` | Микро-клиент HTTP к 127.0.0.1 (без зависимостей) |
| `src-tauri/src/log.rs` | Диагностика оболочки: `eprintln!` на macOS, `kopirka-shell.log` на Windows |
| `src-tauri/capabilities/default.json` | Права IPC: доступ с `http://127.0.0.1:*`, перетаскивание окна, диалог выбора папки |
| `scripts/bundle-server.mjs` | Сборка payload'а сервера в `src-tauri/resources/backend` |
| `scripts/build-intel.mjs` | Intel-сборка одной командой: rust target, x64-Node, x64-пакеты sharp |
| `scripts/make-icons.mjs` | Иконка приложения и шаблонная иконка трея |

## Сборка

Нужны: macOS 13+, Node 22, Rust 1.82+ (`rustup`), Xcode Command Line Tools.
Rust обычно не в `PATH` по умолчанию — тогда `export PATH="$HOME/.cargo/bin:$PATH"`.
Node именно 22: `bundle-server.mjs` кладёт в бандл тот Node, которым его запустили, и
падает с подсказкой, если в `PATH` оказался чужой (проверяются архитектура и мажорная версия).

```bash
cd app
npm install
npm run app:build         # .app и .dmg под архитектуру машины сборки
npm run app:build:intel   # то же под Intel (x86_64), с любой машины
npm run app:dev           # запуск без сборки бандла
```

`app:build` сначала собирает веб (`web/dist`), затем компилирует сервер в JS (`tsc`),
затем складывает payload и только потом зовёт `tauri build`. Отдельно ничего запускать не нужно.

Результат (Apple Silicon):

```
desktop/src-tauri/target.noindex/release/bundle/macos/Копирка.app          135 МБ
desktop/src-tauri/target.noindex/release/bundle/dmg/Копирка_0.3.0_aarch64.dmg   46 МБ
```

Из них ~104 МБ — бинарник Node. Остальное: libvips для `sharp` (18 МБ), сама оболочка
(~11 МБ), интерфейс и код сервера (~1,5 МБ).

### Intel-сборка

`npm run app:build:intel` (`desktop/scripts/build-intel.mjs`) собирает тот же бандл под
`x86_64-apple-darwin`. Одной командой, с машины на Apple Silicon, ручных шагов нет — скрипт
сам делает всё, что отличает Intel-прогон от обычного:

- ставит rust target `x86_64-apple-darwin`, если его ещё нет;
- качает с nodejs.org `node-v22.14.0-darwin-x64.tar.gz`, сверяет sha256 с `SHASUMS256.txt`
  и проверяет, что бинарник — Mach-O x86_64 и отвечает `v22.14.0` под Rosetta;
- ставит x64-пакеты `@img/sharp-darwin-x64` и `@img/sharp-libvips-darwin-x64` тех же версий,
  что в корневом `package-lock.json`;
- зовёт `tauri build --target x86_64-apple-darwin`, передав payload'у `KOPIRKA_TARGET=darwin-x64`,
  `KOPIRKA_NODE_BINARY` и `KOPIRKA_PLATFORM_MODULES`.

Скачанное и поставленное лежит в `desktop/.cache/` (в git не идёт), поэтому второй прогон
ничего не качает. Рабочее дерево скрипт не трогает: `app/node_modules` и `package-lock.json`
остаются под архитектуру машины сборки, x64-пакеты живут отдельным корнем.

```
desktop/src-tauri/target.noindex/x86_64-apple-darwin/release/bundle/macos/Копирка.app        140 МБ
desktop/src-tauri/target.noindex/x86_64-apple-darwin/release/bundle/dmg/Копирка_0.3.0_x64.dmg  48 МБ
```

Проверить Intel-образ на Apple Silicon можно только наполовину. Оболочку — нельзя, а payload
запускается под Rosetta прямо из бандла:

```bash
cd ".../bundle/macos/Копирка.app/Contents/Resources/backend"
KOPIRKA_CONFIG_DIR=/tmp/k/cfg KOPIRKA_LIBRARY_PATH=/tmp/k/lib \
KOPIRKA_PORT=43125 KOPIRKA_NO_OPEN=1 arch -x86_64 ./node server/src/index.js
```

Если после этого `/api/health` отвечает и импорт картинки отдаёт превью — значит x64-сборки
`better-sqlite3`, `sharp` и libvips в бандле рабочие.

Каталог сборки называется `target.noindex`, а не `target` — это задано в
`src-tauri/.cargo/config.toml`. Spotlight не индексирует каталоги с таким суффиксом,
и собранная «Копирка» перестаёт всплывать в поиске по нескольку раз рядом с
установленной. Tauri CLI берёт путь из `cargo metadata`, поэтому бандл ложится туда же.

Иконки перерисовываются отдельно, когда меняется логотип: `npm run icons` в `desktop/`.

## Установка

1. Открыть `.dmg`, перетащить «Копирку» в «Программы».
2. Первый запуск — двойным кликом.

### Замена уже установленной сборки

Своя же свежая сборка ставится поверх старой одной командой. Резервных копий не делаем:
исходники в git, а лишний `Копирка.app.bak` в `/Applications` — это ещё одна «Копирка»
в Spotlight и в Launchpad.

Старые сборки (`target/`, прошлые копии в `/Applications`) не оставлять «на всякий
случай», а удалять: каждая из них регистрируется в LaunchServices и всплывает в Spotlight
и Launchpad. (Прежняя редакция этого абзаца утверждала, что вторая копия ломает
уведомления, — 03.09.2026 это не подтвердилось, см. раздел «Уведомления».)

Идентификатор бандла с 03.09.2026 — `pro.instat.kopirka.desktop`. Прежний
`pro.instat.kopirka` на машине разработки «сожжён»: запрос разрешения на уведомления
система показывает один раз на идентификатор, и закрытое во время запроса приложение
получает отказ навсегда, без записи в настройках. Никому 0.2.0 с прежним идентификатором
не раздавалось, поэтому смена ничего не стоит; конфиг (`~/Library/Application
Support/Kopirka`) и быстрая команда от идентификатора не зависят.

Сначала закрыть приложение — ⌘Q или «Выйти» в меню иконки. Крестика мало: оно живёт
в строке меню. Дальше, из каталога `app`:

```bash
rm -rf /Applications/Копирка.app
ditto "desktop/src-tauri/target.noindex/release/bundle/macos/Копирка.app" /Applications/Копирка.app
open -a Копирка
```

`ditto`, а не `cp -R`: он переносит бандл со всеми правами и расширенными атрибутами,
и `.app` не оказывается битым.

### Предупреждение Gatekeeper

Приложение **не подписано и не нотаризовано** — сертификата разработчика Apple нет.
Что это значит на практике:

- Собранное на этой же машине приложение открывается без вопросов: атрибут карантина
  ставит не сборка, а браузер или мессенджер при скачивании.
- Скачанное по ссылке (или полученное через Telegram, почту, AirDrop) macOS откроет
  не сразу. На macOS 15 и новее правого клика → «Открыть» уже недостаточно: нужно
  запустить приложение, получить отказ, затем зайти в **Системные настройки →
  Конфиденциальность и безопасность** и нажать **«Открыть всё равно»** в блоке,
  который появится внизу. Дальше — подтвердить паролем и открыть ещё раз.
- Быстрый способ для тех, кто дружит с терминалом:

  ```bash
  xattr -dr com.apple.quarantine /Applications/Копирка.app
  ```

Другого честного пути нет: пока нет платного Apple Developer ID и нотаризации,
предупреждение будет появляться у каждого, кому вы отдадите сборку.

### Разрешение на запись экрана

Хоткей ⌥⌘C зовёт системный `screencapture`, а тот требует разрешения на запись экрана.
При первом нажатии macOS сама покажет запрос. Если отказать (или если запрос не
появился), включить вручную:

**Системные настройки → Конфиденциальность и безопасность → Запись экрана** → включить
«Копирку». После выдачи разрешения приложение нужно перезапустить — это требование macOS,
не наше.

Пока разрешения нет, «Копирка» вместо тишины показывает уведомление с этой же подсказкой.

## Как пользоваться

- **Иконка в строке меню** — главный вход. «Показать библиотеку», «Снять область»,
  счётчик «Не разобрано: N» (обновляется раз в 2 секунды, клик открывает этот раздел),
  «Выйти».
- **⌥⌘C в любом приложении** — родная рамка выделения macOS. `Esc` отменяет,
  ничего никуда не уходит. Про удачный снимок скажет общее уведомление (ниже);
  отдельно хоткей говорит только о неудаче — нет разрешения на запись экрана,
  сервер не ответил, снимок уже есть в библиотеке.
- **Быстрая команда Finder «Добавить в Копирку»** появляется сама: приложение ставит
  и обновляет её при каждом запуске (ниже).
- **Крестик окна** не закрывает приложение: оно продолжает жить в строке меню.
  Полный выход — ⌘Q или «Выйти» в меню иконки.
- **Окно таскается за верхнюю панель и за блок логотипа в сайдбаре.** Строки папок,
  карточки, поле поиска и кнопки остаются кликабельными: зоны перетаскивания размечены
  в интерфейсе атрибутом `data-tauri-drag-region`, а кликабельные элементы внутри них
  Tauri пропускает сам.
- **Файлы перетаскиваются в окно как в браузере.** Нативный обработчик перетаскивания
  Tauri в главном окне выключен (`disable_drag_drop_handler`), и drop файлов из Finder
  идёт обычными HTML-событиями страницы. Иначе он глотает всё: его хендлер всегда
  отвечает «событие обработано», wry после такого ответа не зовёт системный
  `performDragOperation`, и до страницы не доходят ни внешний drop, ни `dragover/drop`
  внутреннего переноса карточек по папкам.
- **Кнопка «Выбрать папку…»** в настройках и в онбординге открывает системный диалог
  выбора папки библиотеки. В браузере её нет: там абсолютный путь взять неоткуда,
  поле остаётся единственным входом. Смена пути файлы не переносит — предупреждение
  об этом стоит рядом, до сохранения.
- **Ссылка «Источник» открывается в системном браузере**, а не внутри окна. Любой адрес
  вне `http://127.0.0.1` уходит наружу через `open`; само окно на чужой сайт не уходит —
  вернуться из него было бы нечем.

## Полоса светофора

Окно рисуется без системной полосы заголовка (`titleBarStyle: Overlay`, `hiddenTitle`),
поэтому кнопки светофора по умолчанию ложатся прямо поверх сайдбара. Разведено так:

- оболочка ставит кнопки явно — `traffic_light_position(20, 20)` в `windows.rs`.
  `x = 20` — это поле окна 12 плюс внутреннее поле панели 8, то есть ровно левый край
  строк сайдбара; тут координата означает ровно то, что кажется;
- **`y` — не отступ кружка от верха окна.** В tao (0.35.3, `macos/view.rs:1152`,
  `inset_traffic_lights`) по `y` меняется только высота контейнера титлбара
  (`close.height + y`), а сами кнопки внутри него по вертикали не двигаются: верх
  кружка выходит примерно `y - 9`. Значение 20 подобрано замером на macOS 26 — кружок
  занимает ~11–24.5, центр приходится на середину полосы. Поставленное «по смыслу
  отступа» `y = 12` давало кружок на 3–16.5, почти вплотную к краю окна;
- скрипт инициализации окна синхронно, до первого кадра, ставит на `:root`
  `--kopirka-titlebar-inset: 36px` и `data-kopirka-inset="36"`. 36 = 12 (поле) +
  12 (кнопки) + 12 (зазор); кружки macOS чуть крупнее номинальных 12 и стоят по центру;
- веб берёт `padding-top: var(--kopirka-titlebar-inset, var(--shell-pad))` для оболочки,
  настроек и онбординга. В браузере переменной нет, подставляется обычное поле —
  десктопная особенность в браузерную сборку не протекает.

`--size-topbar` оболочка не трогает: раньше скрипт ждал появления токена в CSS-бандле
и дописывал к нему 28 px — шапка от этого росла, а кнопки всё равно стояли не там.

## Уведомления

Мимо окна может приехать не только файл: сработал автоимпорт папки скриншотов, расширение
Chrome сохранило картинку, нажат ⌥⌘C, выбрано «Добавить в Копирку» в Finder. Раньше про
такое говорил `osascript` из Folder Action и быстрой команды — и macOS рисовала иконку
**Script Editor**, потому что уведомление принадлежит тому процессу, который его показал.

Теперь источник один — само приложение. Сервер ведёт ленту событий в памяти (кольцо на
500) и отдаёт разницу по `GET /api/events?after=<seq>`; оболочка опрашивает её в том же
потоке, где считает «Не разобрано» — раз в две секунды, — и показывает **одно уведомление
на порцию**. Иконка — логотип «Копирки»: баннер шлёт само приложение (`src/notify.rs`).

В ленте два вида записей:

| `kind` | Что это | Что показывает оболочка |
|---|---|---|
| `import` | Файл прошёл конвейер: `added`, `added_similar` или `duplicate` | Сводку по порции: «Добавлено 3 файла в «Сэбач»», «1 файл уже есть в библиотеке», «Добавлено 2 файла · 1 уже был в библиотеке» |
| `notice` | Готовый текст от скрипта снаружи — `POST /api/notify` | Показывает как есть, всегда; заголовок из события или «Копирка» |

Про точный дубль говорим наравне с успехом: человек нажал «Добавить в Копирку» и вправе
услышать «это уже есть», а не тишину. В библиотеку такой файл не попадает, и окно по
таким событиям ничего не дорисовывает.

`POST /api/notify` (`{"body": "...", "title": "..."}`) — вход для тех, кому иначе
пришлось бы звать `osascript`: обработчик быстрой команды говорит через него, что
«Копирка» не отвечает или что часть файлов не дошла. Сервер ничего не показывает сам,
он только кладёт запись в ту же ленту.

### Чем показываем и почему не плагином

`tauri-plugin-notification` снят с зависимостей. На macOS он ходит в notify-rust →
mac-notification-sys, а тот — в `NSUserNotificationCenter`, объявленный устаревшим ещё
в macOS 11. **На macOS 26 этот путь мёртв, причём молча**: `show()` не возвращает ошибку,
баннер не появляется, и приложение даже не заводится в списке Центра уведомлений
(`defaults read com.apple.ncprefs apps` — тогдашнего идентификатора `pro.instat.kopirka`
там не было вовсе). Проверено 03.09.2026 на 26.5.1: контрольный `osascript` в ту же секунду
показывал баннер, «Копирка» — нет. То есть уведомления от приложения не работали
никогда, и ошибку было не видно: плагин глотает и `set_application`, и `show`.

`src/notify.rs` показывает баннеры сам, через живой `UNUserNotificationCenter`. Классы
берутся из рантайма (`AnyClass::get` + `msg_send!`), потому что `objc2`,
`objc2-foundation` и `block2` уже лежат в дереве ради tao и wry — новых зависимостей
не появилось, типизированный `objc2-user-notifications` не понадобился.

Что из этого следует:

- **Нужно разрешение, и просить его надо после старта цикла событий.** Запрос стоит в
  обработчике `RunEvent::Ready`, а не в `setup`: `setup` выполняется до
  `applicationDidFinishLaunching`, и в этот момент UN* ещё не считает процесс запущенным
  приложением. Отказали в ответ на запрос — включить обратно можно в **Системные
  настройки → Уведомления → Копирка**, но только если приложение вообще успело туда
  попасть (см. ниже про несожжённый идентификатор).
- **Бандл должен быть подписан.** `tauri build` до 03.09.2026 оставлял `.app` вовсе без
  подписи — каталога `Contents/_CodeSignature` в нём не было, и `codesign -v` на бандле
  падал. Для macOS это неподписанное приложение, и `requestAuthorization` отвечает ему
  `UNErrorDomain error 1` («Notifications are not allowed for this application»), не
  показывая никакого запроса. Проверено 03.09.2026 в лоб: одна и та же сборка со
  свежим идентификатором **без подписи** — отказ, **с `codesign -f -s - --deep`** —
  запрос появляется. Поэтому в `tauri.conf.json` выставлены `"signingIdentity": "-"`
  (ad-hoc-подпись при сборке) и `"hardenedRuntime": false` — второе намеренно: с
  ad-hoc-подписью и включённым hardened runtime проверка библиотек могла бы не пустить
  наш же `node` и его нативные модули, а до этой правки hardened runtime всё равно
  не применялся, потому что подписи не было вовсе.

  Если по какой-то причине подпись при сборке не встала, лечится вручную:

  ```bash
  codesign -f -s - --deep "desktop/src-tauri/target.noindex/release/bundle/macos/Копирка.app"
  ```
- **Запрос показывается один раз на идентификатор бандла — и его надо дождаться.**
  Если приложение закрыть, пока запрос висит на экране, macOS засчитывает отказ
  **навсегда**. Дальше при каждом запуске приходит «Notifications are not allowed for
  this application», нового запроса нет, и — что хуже всего — приложения **нет ни в
  `com.apple.ncprefs`, ни в списке «Системные настройки → Уведомления»**, то есть
  включить его обратно там не получится. Проверено 03.09.2026 в лоб: один и тот же
  бандл, та же подпись, то же место — первый запуск показывает запрос, второй (после
  `pkill`, без ответа на запрос) уже получает отказ.

  Отсюда правило для проверок: **никогда не убивать приложение при висящем запросе** —
  сначала ответить. Идентификатор, который успели сжечь, восстановлению средствами
  приложения не поддаётся; лечится только сменой `identifier` в `tauri.conf.json`.

  Начиная с 0.2.0 приложение сначала читает сохранённый статус
  (`getNotificationSettingsWithCompletionHandler:`) и пишет его в stderr, поэтому
  «отказано» и «система не дала спросить» больше не выглядят одинаково.
- **Бандл не должен лежать во временном каталоге.** Приложение в `/private/tmp`
  (а значит, и в `/tmp`) получает отказ, даже если идентификатор совершенно свежий:
  статус остаётся `notDetermined` — то есть система его не спрашивала, — а
  `requestAuthorization` всё равно отвечает «Notifications are not allowed». Тот же
  бандл, скопированный в `~/Documents/…`, сразу показывает запрос. Проверено
  03.09.2026: это единственное отличие между двумя прогонами.

  Число копий на диске при этом **ни при чём** — запрос появлялся и тогда, когда рядом
  лежали четыре «Копирки». (В более ранней редакции этого файла было написано обратное;
  проверка не подтвердилась.)
- **Только из `.app` и только через LaunchServices.** Проверять надо запуском бандла,
  а не бинарником из `Contents/MacOS`:

  ```bash
  open -n --stderr /tmp/kopirka.log \
    --env "KOPIRKA_CONFIG_DIR=/tmp/kopirka-test/cfg" --env "KOPIRKA_PORT=43122" \
    -a "desktop/src-tauri/target.noindex/release/bundle/macos/Копирка.app"
  ```

  `--stderr` — единственный простой способ увидеть, что приложение пишет о себе:
  из-под LaunchServices его stderr иначе не попадает никуда, включая системный лог.
- **Проверка перед обращением к UN*.** Если LaunchServices не знает процесс как
  приложение (перенос из карантина при запуске с `.dmg` или из Загрузок, битая
  регистрация), `currentNotificationCenter` бросает исключение — и поймать его нельзя:
  бросок происходит внутри `dispatch_once`, а libdispatch гасит процесс сам, не пропуская
  исключение наружу. Поэтому перед вызовом смотрим `NSRunningApplication
  .currentApplication.bundleIdentifier`: нет его — не трогаем UN* вовсе, строка в stderr,
  приложение работает дальше без уведомлений.
- **Баннер без звука.** Файл, приехавший мимо окна, — не повод перебивать то, чем
  человек занят.
- **Пока «Копирка» впереди всех окон, баннера не будет** — так macOS ведёт себя с любым
  приложением без делегата `UNUserNotificationCenterDelegate`. На практике это не мешает:
  когда файл приезжает мимо окна, впереди обычно Chrome, Finder или то, что снимают
  по ⌥⌘C, а если впереди «Копирка» — карточка и так появится в сетке.

Первый опрос после запуска только запоминает точку отсчёта: накопившееся, пока
приложение было выключено, не сыплется пачкой уведомлений.

Перетаскивание и ⌘V решаются по фокусу главного окна. Пока на окно смотрят, они молчат:
там уже показан свой тост, и системное уведомление было бы вторым сообщением об одном и
том же. Если окно не в фокусе, спрятано или закрыто — уведомление приходит: этим путём
работает быстрая команда Finder «Добавить в Копирку», а показать тост в такой момент
некому. По той же логике окно опрашивает `/api/events` само (раз в 3 с, только пока
вкладка видима) и дорисовывает карточку без перезагрузки.

### Windows: тост и ярлык в «Пуске»

В Windows-сборке баннеры показывает штатный `tauri-plugin-notification` — он подключён
только там (`Cargo.toml`, `[target.'cfg(windows)'.dependencies]`). Причина, по которой
плагин сняли с macOS, на Windows не действует: под капотом у него не мёртвый
`NSUserNotificationCenter`, а живой WinRT-тост.

**Уведомления заработают только у приложения, поставленного установщиком.** Тост в Windows
принадлежит не процессу, а зарегистрированному AppUserModelID, а AUMID появляется вместе
с ярлыком в меню «Пуск» — его кладёт NSIS-установщик и прописывает в ярлык
`System.AppUserModel.ID`. У бинарника, запущенного из папки сборки, тостов не будет,
и это не поломка. Плагин учитывает это сам: `app_id` он ставит, только когда исполняемый
файл лежит не в `target\debug` и не в `target\release`.

Разрешения спрашивать не нужно — системного запроса на уведомления в Windows нет, и плагин
всегда отвечает `Granted`. В капабилити `notification:default` намеренно не добавлен:
оболочка зовёт плагин из Rust, а ACL стоит только на пути через `invoke`.

Диагностика оболочки на Windows идёт не в stderr: приложение собрано с
`windows_subsystem = "windows"`, консоли у процесса нет, и `eprintln!` пишет в никуда.
Те же строки дописываются в `kopirka-shell.log` рядом с конфигом — в
`%APPDATA%\Kopirka`. Ротации нет: дошёл до 256 КБ — файл начинается заново.

## Быстрая команда Finder

«Добавить в Копирку» в контекстном меню Finder ставит и обновляет само приложение — при
каждом старте, в фоне, после того как поднялся сервер. Участникам клуба нельзя предлагать
запускать shell-скрипты, а разошедшиеся копии обработчика уже однажды стоили месяцев
уведомлений с чужой иконкой.

Приложение раскладывает три файла:

```
~/Library/Application Support/Kopirka/quick-add.sh              (chmod +x)
~/Library/Services/Добавить в Копирку.workflow/Contents/Info.plist
~/Library/Services/Добавить в Копирку.workflow/Contents/document.wflow
```

и, если что-то изменилось, зовёт `/System/Library/CoreServices/pbs -flush` — без этого
пункт появится только после перелогина. Сравнение по содержимому: совпало — не пишем
и `pbs` не дёргаем. Ошибки уходят в stderr, запуск приложения из-за них не падает.

Тексты этих трёх файлов лежат в `app/quick-action/` и только там: приложение зашивает их
через `include_str!` (`src/quickaction.rs`), а `quick-action/install.sh` копирует те же
файлы для ручной установки без приложения. Правятся только в `quick-action/`.

Когда задан `KOPIRKA_CONFIG_DIR`, автоустановка не выполняется: изолированный экземпляр
не должен переписывать пользовательскую службу, которая ходит на порт из настоящего
конфига.

## Открытый IPC

Интерфейс приходит с `http://127.0.0.1:<порт>`, а для Tauri это **удалённый** origin, а не
локальный: `frontendDist` не совпадает с этим адресом, поэтому любой вызов оттуда по
умолчанию отбрасывается списком доступа. Из-за этого не работало перетаскивание окна —
скрипт Tauri зовёт `plugin:window|start_dragging` и получал отказ.

Решение (D4 от 02.09.2026) — `capabilities/default.json`: блок
`"remote": { "urls": ["http://127.0.0.1:*", "http://localhost:*"] }` плюс явные
разрешения `core:window:allow-start-dragging` (в `core:window:default` его нет) и
`dialog:allow-open` — на нём держится выбор папки библиотеки. Блок `remote` действует
на всю капабилити, поэтому оба разрешения доступны интерфейсу с локального адреса.
Сузить шаблон до одного порта нельзя — порт настраиваемый.

Цена решения: IPC доступен всему, что ответит на `127.0.0.1` в этом окне. Практически
это только наш же сервер: переход на чужой адрес окно теперь не выполняет.
В `tauri.conf.json` для этого ничего не нужно — в Tauri 2 старого
`dangerousRemoteDomainIpcAccess` нет, удалённые origin описываются только в капабилити.

## Как удалить

```bash
rm -rf /Applications/Копирка.app
rm -rf ~/Library/Application\ Support/Kopirka     # конфиг, лог и обработчик быстрой команды
rm -rf ~/Library/Services/Добавить\ в\ Копирку.workflow   # пункт контекстного меню Finder
/System/Library/CoreServices/pbs -flush
```

Библиотека (`~/Pictures/Копирка` по умолчанию) — обычная папка с файлами и `library.db`.
Удаление приложения её не трогает; удалять её нужно руками и осознанно.

## Известные ограничения

- **Два образа, оба собираются здесь.** `Копирка_0.3.0_aarch64.dmg` — Apple Silicon,
  `Копирка_0.3.0_x64.dmg` — Intel (`npm run app:build:intel`). Universal-бандла нет и не
  планируется: внутри целый Node, склейка удвоила бы вес ради машин, которых у клуба почти нет.
- **Intel-сборку живьём на Intel-Mac никто не проверял.** 04.09.2026 проверен только payload:
  сервер из готового бандла поднят под Rosetta на этой же машине — `/api/health`, импорт
  картинки и превью проходят, то есть x64-сборки `better-sqlite3`, `sharp` и libvips рабочие.
  Оболочка, трей, хоткей ⌥⌘C и уведомления на Intel не проверены.
- **Windows-версия собирается только в CI и живьём ещё не проверена.** Установщик NSIS под
  x64 делает GitHub Actions (`.github/workflows/build-windows.yml`): на Mac Windows-бандл
  собрать нечем — нет MSVC и makensis. Кросс-конвейера, как `build-intel.mjs` для Intel, для
  неё не нужно: на раннере хост совпадает с целью. Чего в Windows-версии нет по решению
  от 09.09.2026 — захвата области экрана, автоимпорта папки и пункта контекстного меню
  Проводника. Параметры кросс-сборки payload'а (`KOPIRKA_NODE_BINARY`, `KOPIRKA_TARGET`,
  `KOPIRKA_PLATFORM_MODULES`) остаются в силе и используются Intel-сборкой.
- **Нет подписи, нотаризации и автообновления.** Новая версия — новый `.dmg` руками.
- **Порт берётся из конфига.** Если сменить `serverPort` в
  `~/Library/Application Support/Kopirka/config.json`, оболочка пойдёт туда же.
- **Один сервер на порт.** Порт занят — приложение сначала спрашивает у того, кто на нём
  сидит, `/api/health`:
  - ответила «Копирка» (сервер из терминала или второй экземпляр) — приложение не поднимает
    свой сервер, а просто показывает её интерфейс. При выходе чужой процесс не гасится;
  - ответил кто-то посторонний — аварийное окно: «Порт N занят другой программой» и две
    кнопки, «Выйти» и «Сбросить порт на 43117». Вторая возвращает `serverPort` в конфиге
    к стандартному значению и перезапускает приложение. Если конфиг не читается или порт
    задан переменной `KOPIRKA_PORT`, окно честно об этом скажет и ничего не сломает.
- **Счётчик в трее и уведомления обновляются раз в 2 секунды** — опросом, а не
  мгновенно после импорта. Без запущенного приложения уведомлений нет вовсе:
  файлы уедут в библиотеку, но сказать об этом будет некому.
- Размер `.app` — 135 МБ (Intel — 140 МБ), потому что внутри целый Node. Это цена
  «поставил и работает».

## Переменные окружения

В обычной работе не нужны, но оболочка их пробрасывает серверу — этим удобно гонять
тесты на временной библиотеке, не трогая настоящую:

```bash
open -n \
  --env "KOPIRKA_LIBRARY_PATH=/tmp/kopirka-test/lib" \
  --env "KOPIRKA_CONFIG_DIR=/tmp/kopirka-test/cfg" \
  --env "KOPIRKA_PORT=43317" \
  -a /Applications/Копирка.app
```

| Переменная | Что делает |
|---|---|
| `KOPIRKA_LIBRARY_PATH` | Путь библиотеки в обход конфига |
| `KOPIRKA_CONFIG_DIR` | Другая папка конфига и лога |
| `KOPIRKA_PORT` | Другой порт (важен и оболочке, и серверу) |
| `KOPIRKA_PARENT_STDIN` | Ставит оболочка. Сервер следит за stdin и уходит вместе с родителем |

Последняя — не для ручного использования. Оболочка отдаёт серверу свой stdin как поводок:
когда приложение умирает любым способом, включая `kill -9`, труба закрывается и сервер
завершается сам. Без этого осиротевший Node держал бы порт и следующий запуск не состоялся бы.
