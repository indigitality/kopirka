# Копирка для macOS

Десктопная упаковка «Копирки» на Tauri 2: окно с интерфейсом, иконка в строке меню,
глобальный хоткей на снимок области и локальный Node-сервер внутри бандла.

Ничего доустанавливать не нужно — Node, `sharp` и `better-sqlite3` лежат внутри `.app`.

## Что внутри

| Путь | Что это |
|---|---|
| `src-tauri/src/main.rs` | Запуск, меню, обработка выхода |
| `src-tauri/src/backend.rs` | Node-сервер как дочерний процесс: старт, health-check, гашение |
| `src-tauri/src/tray.rs` | Иконка строки меню и счётчик «Не разобрано» |
| `src-tauri/src/capture.rs` | ⌥⌘C: `screencapture -i` → `POST /api/import/capture` |
| `src-tauri/src/windows.rs` | Главное и аварийное окна, инъекция стиля под светофор |
| `src-tauri/src/menu.rs` | Русское меню приложения; ⌘Q идёт через наш код |
| `src-tauri/src/http.rs` | Микро-клиент HTTP к 127.0.0.1 (без зависимостей) |
| `scripts/bundle-server.mjs` | Сборка payload'а сервера в `src-tauri/resources/backend` |
| `scripts/make-icons.mjs` | Иконка приложения и шаблонная иконка трея |

## Сборка

Нужны: macOS на Apple Silicon, Node 22+, Rust 1.82+ (`rustup`), Xcode Command Line Tools.
Rust обычно не в `PATH` по умолчанию — тогда `export PATH="$HOME/.cargo/bin:$PATH"`.

```bash
cd app
npm install
npm run app:build     # .app и .dmg
npm run app:dev       # запуск без сборки бандла
```

`app:build` сначала собирает веб (`web/dist`), затем компилирует сервер в JS (`tsc`),
затем складывает payload и только потом зовёт `tauri build`. Отдельно ничего запускать не нужно.

Результат:

```
desktop/src-tauri/target/release/bundle/macos/Копирка.app          135 МБ
desktop/src-tauri/target/release/bundle/dmg/Копирка_0.1.0_aarch64.dmg   46 МБ
```

Из них ~104 МБ — бинарник Node. Остальное: libvips для `sharp` (18 МБ), сама оболочка
(~11 МБ), интерфейс и код сервера (~1,5 МБ).

Иконки перерисовываются отдельно, когда меняется логотип: `npm run icons` в `desktop/`.

## Установка

1. Открыть `.dmg`, перетащить «Копирку» в «Программы».
2. Первый запуск — двойным кликом.

### Предупреждение Gatekeeper

Приложение **не подписано и не нотаризовано** — сертификата разработчика Apple нет.
Что это значит на практике:

- Собранное на этой же машине приложение открывается без вопросов: атрибут карантина
  ставит не сборка, а браузер или мессенджер при скачивании.
- Скачанное по ссылке (или полученное через Telegram, почту, AirDrop) macOS откроет
  не сразу. На macOS 15 и новее правого клика → «Открыть» уже недостаточно: нужно
  запустить приложение, получить отказ, затем зайти в **Системные настройки →
  Конфиденциальность и безопасность** и нажать **«Открыть всё равно»** в блоке,
  который появится внизу. Дальше — подтвердить паролем и открыть ещё раз.
- Быстрый способ для тех, кто дружит с терминалом:

  ```bash
  xattr -dr com.apple.quarantine /Applications/Копирка.app
  ```

Другого честного пути нет: пока нет платного Apple Developer ID и нотаризации,
предупреждение будет появляться у каждого, кому вы отдадите сборку.

### Разрешение на запись экрана

Хоткей ⌥⌘C зовёт системный `screencapture`, а тот требует разрешения на запись экрана.
При первом нажатии macOS сама покажет запрос. Если отказать (или если запрос не
появился), включить вручную:

**Системные настройки → Конфиденциальность и безопасность → Запись экрана** → включить
«Копирку». После выдачи разрешения приложение нужно перезапустить — это требование macOS,
не наше.

Пока разрешения нет, «Копирка» вместо тишины показывает уведомление с этой же подсказкой.

## Как пользоваться

- **Иконка в строке меню** — главный вход. «Показать библиотеку», «Снять область»,
  счётчик «Не разобрано: N» (обновляется раз в 30 секунд, клик открывает этот раздел),
  «Выйти».
- **⌥⌘C в любом приложении** — родная рамка выделения macOS. `Esc` отменяет,
  ничего никуда не уходит. После съёмки — системное уведомление с результатом.
- **Крестик окна** не закрывает приложение: оно продолжает жить в строке меню.
  Полный выход — ⌘Q или «Выйти» в меню иконки.

## Как удалить

```bash
rm -rf /Applications/Копирка.app
rm -rf ~/Library/Application\ Support/Kopirka     # конфиг и лог
```

Библиотека (`~/Pictures/Копирка` по умолчанию) — обычная папка с файлами и `library.db`.
Удаление приложения её не трогает; удалять её нужно руками и осознанно.

## Известные ограничения

- **Только Apple Silicon.** Сборка — `aarch64`. Под Intel нужен второй прогон с другим
  target и другим бинарником Node.
- **Только macOS.** Windows-сборки нет. Структура к ней готова: `bundle-server.mjs`
  принимает `KOPIRKA_NODE_BINARY` (другой бинарник Node) и `KOPIRKA_TARGET`
  (другая платформа для prebuild'ов `better-sqlite3` и пакетов `sharp`).
- **Нет подписи, нотаризации и автообновления.** Новая версия — новый `.dmg` руками.
- **Один экземпляр.** Порт 43117 занят — приложение показывает окно с объяснением и
  кнопкой «Выйти», а не белый экран. Это же окно появится, если на порту висит
  сервер, запущенный из терминала через `npm start`.
- **Порт берётся из конфига.** Если сменить `serverPort` в
  `~/Library/Application Support/Kopirka/config.json`, оболочка пойдёт туда же.
- **Счётчик в трее обновляется раз в 30 секунд**, а не мгновенно после импорта.
- Размер `.app` — 135 МБ, потому что внутри целый Node. Это цена «поставил и работает».

## Переменные окружения

В обычной работе не нужны, но оболочка их пробрасывает серверу — этим удобно гонять
тесты на временной библиотеке, не трогая настоящую:

```bash
open -n \
  --env "KOPIRKA_LIBRARY_PATH=/tmp/kopirka-test/lib" \
  --env "KOPIRKA_CONFIG_DIR=/tmp/kopirka-test/cfg" \
  --env "KOPIRKA_PORT=43317" \
  -a /Applications/Копирка.app
```

| Переменная | Что делает |
|---|---|
| `KOPIRKA_LIBRARY_PATH` | Путь библиотеки в обход конфига |
| `KOPIRKA_CONFIG_DIR` | Другая папка конфига и лога |
| `KOPIRKA_PORT` | Другой порт (важен и оболочке, и серверу) |
| `KOPIRKA_PARENT_STDIN` | Ставит оболочка. Сервер следит за stdin и уходит вместе с родителем |

Последняя — не для ручного использования. Оболочка отдаёт серверу свой stdin как поводок:
когда приложение умирает любым способом, включая `kill -9`, труба закрывается и сервер
завершается сам. Без этого осиротевший Node держал бы порт и следующий запуск не состоялся бы.
