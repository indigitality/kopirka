# Лендинг «Копирки»

Статический одностраничный сайт продукта: React 19 + Vite 7 + Tailwind 4, тёмная
тема, никакого сервера и API. Отдельный workspace `landing` внутри `app/`
(рядом с `server` и `web`).

Первоисточник дизайна — файл **Scratchpad** в Paper, страница «лендинг», артборд
**`H0E-0` «Лендинг · A · Чёрная галерея»** (1440×7826). Девять секций артборда
разложены по одному компоненту на секцию в `src/components/`.

## Запуск

```bash
# из app/
npm install                        # ставит зависимости всех workspace-ов
npm run dev       --workspace=landing   # дев-сервер, http://localhost:5180
npm run build     --workspace=landing   # tsc -b && vite build → landing/dist
npm run preview   --workspace=landing   # раздача собранного dist, тот же 5180
npm run typecheck --workspace=landing
```

Порт **5180** выбран так, чтобы не пересекаться с занятыми в проекте: 5173 — веб
приложения, 5174 — его песочница, 6006 — Storybook, 5176/5177 — прогоны
`tests/ui`. Переопределяется переменной `KOPIRKA_LANDING_PORT`.

## Откуда что взято

- **Токены** — `src/styles/tokens.css`. Значения скопированы из первоисточника
  `app/web/src/styles/tokens.css` (он снят с фрейма «Для правок» R01–R14 в
  Paper). Правки вносить там и переносить сюда, а не наоборот. Своего здесь
  только холст `--color-canvas: #050505` (так нарисован фрейм A) и нейтральная
  текстовая шкала лендинга `--color-display/lead/body/faint/hairline`.
- **Логотип** — `src/components/Logo.tsx`, копия
  `app/web/src/components/ui/Logo.tsx`. Контуры сняты с узлов Paper один в один;
  единственное отличие копии — цвет слова задаётся пропом `wordColor`, знак
  всегда лаймовый.
- **Движение** — `src/lib/motion.ts`: пружина 380/32, blur 8→0, y 12→0,
  нажатие scale 0.97. Те же числа, что в `app/web/src/lib/motion.ts`.
- **Кнопки** — `src/components/Button.tsx`. Радиус всегда `--radius-md` 8
  (в макете нарисованы пилюли 999 — игнорируются по правке Сергея), высоты
  только две: 32 в навигации и 40 на первом экране.

## Медиа

Всё лежит в `public/media/`, подключается абсолютным путём `/media/...`.

| Файл | Что это |
|---|---|
| `hero-library.webp` | снимок окна приложения для первого экрана; исходник — `work/промо-ролик (это сделал клод)/кадры-интерфейса-v2/01-library.png` |
| `way-01…05-*.webp` | иллюстрации пяти способов захвата |
| `order-*.webp` | иллюстрации бенто «Порядок без усилий» |

`way-*` и `order-*` — **временные**: это панели-иллюстрации, выгруженные из Paper
(`export`, png 4x) и подогнанные под слот. Ждут записей экрана от Сергея.

Конвейер подгонки (нужен `ffmpeg`; `cwebp` на этой машине нет):

1. экспорт внутреннего узла иллюстрации из Paper в png 4x;
2. кроп по границам содержимого;
3. масштаб так, чтобы иллюстрация заняла всю ширину панели, но не больше 90 %
   её высоты;
4. добивка до **16:10** цветом `--color-panel` `#1C1D1F` и упаковка в webp.

Итог — каждый файл 1600×1000. Поле уже внутри картинки, поэтому `MediaSlot`
своего не добавляет: иначе поле складывается дважды и иллюстрация тонет.

### Подменить иллюстрацию записью экрана

`MediaSlot` с самого начала умеет видео. В `src/components/FiveWays.tsx` у нужной
вкладки меняется только описание медиа:

```ts
// было
media: { kind: 'image', src: '/media/way-02-extension.webp' },
// стало
media: { kind: 'video', src: '/media/way-02-extension.mp4', poster: '/media/way-02-extension.webp' },
```

Видео проигрывается `autoplay muted loop playsinline`. Кадр записи тоже приводить
к **16:10** — слот растягивает медиа на всю панель (`object-cover`), и другое
соотношение обрежется по краям.

## Две платформы — `src/platform.ts`

Сборок с 09.09.2026 две: macOS (два образа) и Windows x64 (NSIS-установщик).
Факты о них лежат в `src/links.ts` записью `PLATFORMS` по системам — файлы, вес,
требования, инструкция. Слова, которые от системы зависят, — в
`src/platform.ts`: хоткеи (`hotkey('⌘V', platform)` → `Ctrl+V`), имя файлового
менеджера (Finder ↔ Проводник), метод определения системы гостя (`usePlatform`).
Значения строк — копия `app/web/src/lib/platform.ts`: человек должен встретить в
приложении ровно то, что прочитал на странице.

Правило то же, что в приложении: **набор macOS — умолчание**, Windows-набор
показывается только когда браузер прямо сказал «Windows». Телефон, планшет и
Linux считаются `other`: им страница показывает нейтральное «Скачать» и
требования обеих систем.

Проверить обе версии текста глазами: `?os=windows`, `?os=macos`, `?os=other`
в адресе.

Чего в Windows-сборке нет — захвата области (⌥⌘C), автоимпорта папки скриншотов,
пункта в контекстном меню Проводника. На странице об этом сказано в двух местах и
больше нигде: приписка под кнопкой Windows в блоке «Скачать» и метка
«только macOS» у первого способа в «Пяти способах». Иллюстрации в «Пяти
способах» и «Порядке» остались macOS-выгрузками (в `order-search.webp` видно
⌘K) — заменить их можно только записями экрана Windows-сборки.

## Что ещё не решено — `[?]` в `src/links.ts`

Все внешние ссылки и факты релиза лежат там одним файлом; неизвестное — это
константа со значением `'#'` (или `null`, если это число) и пометкой `[?]` в
комментарии, чтобы сайт собирался и было видно, что спросить у Сергея.

- `PLATFORMS.windows.size` — вес установщика Windows: файл ещё не собран
  (`.github/workflows/build-windows.yml`), и вес в строке требований просто не
  показывается, пока цифры нет;
- `DONATE` и `DONATE_AMOUNTS` — канал доната и суммы-подсказки;
- `INSTAT` — домен студии; взят из чернового текста фрейма A, Сергей не
  подтверждал;
- логотипа Instat нет вовсе — в `Instat.tsx` стоит текстовая заглушка.

Подтверждены и менять без причины не надо: `RELEASE` (0.2.0, сентябрь 2026),
`PLATFORMS` (имена файлов, требования, вес macOS-образов), `GITHUB`, `TELEGRAM` —
источники `wiki/RELEASE.md`, `app/README.md`, `desktop/scripts/build-windows.mjs`.

Файлы раздачи кладёт на сервер `work/лендинг (это сделал клод)/деплой/deploy.sh`,
а `Content-Disposition` для каждого имени прописан картой в `provision.sh`. Новый
файл в `PLATFORMS` без строки в обоих скриптах отдастся 404 — это не забыть.

## Скриншоты и проверки

Способ тот же, что у регрессионного прогона приложения (`app/tests/ui/`):
**`puppeteer-core` + системный Google Chrome**, без скачивания браузера.

```js
const browser = await puppeteer.launch({
  executablePath: '/Applications/Google Chrome.app/Contents/MacOS/Google Chrome',
  headless: true,
  defaultViewport: { width: 1440, height: 900, deviceScaleFactor: 2 },
  args: ['--force-color-profile=srgb', '--font-render-hinting=none', '--enable-unsafe-swiftshader'],
});
```

`--enable-unsafe-swiftshader` нужен, чтобы в headless поднялся WebGL и отрисовался
шейдерный фон первого экрана; без него страница честно падает на запасной
canvas-фон.

**`app/tests/ui/node_modules` на этой машине пуст** — `tests/ui` не workspace, а
своя папка со своим `package.json`. Перед прогоном ставить зависимость отдельно:
`npm install` внутри `app/tests/ui/`, либо `npm i puppeteer-core` во временной
папке и запускать скрипт оттуда.

Готовые снимки лежат в
`work/лендинг (это сделал клод)/скриншоты/`.

## Что проверять после правок

- `npm run typecheck --workspace=landing` и `npm run build --workspace=landing`
  чистые, предупреждения о размере чанка нет (шейдер вынесен в ленивый чанк);
- горизонтального скролла нет на 1440 / 1024 / 768 / 390;
- вкладки «Пять способов»: лоадер 7 с, автопереход по кругу, пауза по наведению
  и вне экрана, клик и стрелки ↑↓;
- `?os=windows` и `?os=macos`: в блоке «Скачать» первой идёт группа своей
  системы, приписка про подпись — своей системы, хоткеи в «Пяти способах» и
  «Порядке» переключаются между ⌘ и Ctrl+, путь библиотеки — между
  `~/Pictures/Копирка` и `%USERPROFILE%\Pictures\Копирка`;
- `document.fonts.check('500 14px "Inter Tight Variable"')` → `true`;
- при `prefers-reduced-motion` фон первого экрана статичен (в `#top` нет `canvas`).
